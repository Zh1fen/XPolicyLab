# 0001：以可复现 infra 为当前范围，使用可恢复的策略视图

- 日期：2026-11-15
- 状态：采用；默认策略集合由 [0002](0002-user-selected-policies.md) 替代，其余决定继续适用
- 依据：用户本次明确指令；仓库 `6baccd57` 的本地代码与资产检查

## 背景

原仓库包含 77 个策略和一个 demo，共 78 个 adapter、9,750 个 policy 跟踪文件。
用户希望先建立好用的研究 infra，减少未使用策略污染开发上下文，并让 agent 有稳定的文档参考。
Pi_05 已有未提交的 LIBERO 训练修改、独立服务脚本、uv 环境和两份训练 step。

## 决定

1. 当前只做 infra；Harness 和记忆研究不进入本阶段设计或实现。
2. 默认工作区保留 `demo_policy`、`Pi_05`、`ACT`、`DP`，其余 74 个 adapter 用 Git sparse checkout 收起。
3. 全量源码仍由 Git 保存；配置和脚本使新 clone 可以重建同样视图，按需展开或恢复全部。
4. 不变更训练配方、机器人定义和历史产物；先保存事实、区分协议路径，再做可审计的后续改动。
5. 建立简短的文档索引、状态页、操作手册、决策、工作记录和实验记录，配套轻量自动检查。

## 其他选择与取舍

直接删除 74 个策略会制造庞大删除 diff，增加未来同步上游和恢复参考实现的成本。
移到仓库内 archive 仍容易被搜索加载；移到外部目录则使可恢复性依赖本机路径。
稀疏视图保留 Git 中的来源与许可，也不影响 adapter 的包名和共享相对路径。

代价是 sparse 设置属于本地 Git 元数据，clone 不会自动继承；需执行文档中的 `focus` 命令。
`git ls-files` 仍显示全量文件，agent 检索应优先使用磁盘上的 `rg --files` 与明确路径。
收起脚本拒绝隐藏带本地修改或资产的策略；遇到这种情况应保持该策略可见或先保存资产。

未来若需要真正裁剪发布包，再另记决策，明确许可保留、来源版本与恢复方案。
