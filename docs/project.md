# RoboLab：范围与验收

## 当前目标

RoboLab 复用现有 adapter、服务端、数据转换和环境接线，做一套后续科研可长期使用的 infra。
项目来源与兼容层说明见 [UPSTREAM.md](../UPSTREAM.md)。
第一阶段以可复现前沿策略为交付目标；不以模型数量或文档数量作为完成标准。
当前不实现 Harness、记忆、任务规划、失败恢复或相关预留抽象。

任务来源为用户于 2026-11-15 的明确要求，以及同日提供的
《面向具身智能的Harness框架设计与记忆增强机制研究_毕设任务书.docx》。
任务书中的后续研究目标不属于本阶段验收；其中参考文献也未在本次整理中独立核实。
本文件记录工程范围，不替代正式任务书。

## 默认选择

| 组件 | 当前选择 | 理由 |
| --- | --- | --- |
| 共享 infra | 保留 XPolicyLab 的协议、契约和共享 helpers | 减少另起炉灶和接口分叉 |
| 主线策略 | Pi_05 | 已有 uv 环境、本地数据、训练改动和 checkpoint 可接续 |
| 接线检查 | demo_policy | 无模型权重即可检查公共链路 |
| 其他保留策略 | GR00T_N17、TinyVLA、FastWAM、LingBot_VA、LingBot_VLA、StarVLA | 用户于 2026-11-16 明确选择；按复现需要确定顺序 |
| 起步环境 | 现有 LIBERO 工作区 | 已有可审计的本地资产；原生路径需与标准协议区分 |
| 后续环境 | 按实际研究需求接入 RoboTwin / RoboDojo 等 | 先完成一条可复现闭环，再扩展 |

当前八个入口由用户确认，ACT / DP 已收起；目录名中的 `StarVLA`、`Pi_05` 分别对应用户所说的 starvla、pi05。
选择背景见[决策 0002](decisions/0002-user-selected-policies.md)，保留状态不代表已验证模型效果。

## 阶段与完成条件

| 阶段 | 完成条件 | 证据 |
| --- | --- | --- |
| P0：工作区与工程规范 | 精简视图可恢复；agent 有明确阅读顺序；开发、实验和工作记录有入口；轻量检查可重复运行 | Git diff、检查命令、工作记录 |
| P1：公共链路 | 无权重 demo 在 ws 上完成 reset、单条/批量观测与动作；覆盖原始数组及编码图像；失败可定位 | smoke 日志、命令与环境版本 |
| P2：真实模型基线 | 固定 Pi_05 checkpoint、数据版本、预处理、动作语义，在固定任务集和 seed 上跑完评测 | 实验记录、逐任务成功/总数、失败原因、日志和视频位置 |
| P3：可复现交付 | 在另一干净环境按文档重跑，结果满足预先声明的容差；统一入口的覆盖范围明确 | 第二次运行记录、版本锁定、结果对比 |

P2 前先确认要复现的论文/公开配方、精确 checkpoint 和目标指标；自行训练的 LoRA 结果不能直接标成官方 π0.5 复现。
训练属于按需能力：先固定现有 checkpoint 验证评测，再决定是否重训，避免用昂贵训练掩盖接线问题。

## 结果口径

“代码存在”“静态检查通过”“链路跑通”“真实任务成功”“复现目标效果”是不同证据等级。
结果必须报告任务集、episode 数、seed、checkpoint、环境版本和动作/图像预处理。
比较模型时统一任务、环境、初始状态与评测预算；成功率同时报告成功数和总数。
从文件名推断的旧视频统计不能代替正式评测记录。

当前完成情况与下一步只维护在 [STATUS.md](STATUS.md)，避免在多份规划里各写一遍。
